# ✍️ 学术论文写作

[English](README.md) | **简体中文**

- 🛡️ **还在为 AI 反复添加无谓的自我辩解、把贡献越写越弱而头疼？**

- 🔗 **每句话单看都懂，连起来却缺少逻辑，读完仍不知道重点在哪里？**

- 🖋️ **明明想要专业、自然的论文表达，得到的却是生硬搭配和口语化总结？**

- 🧭 **实验做了不少，论文却像工作汇报，读者依然看不出你究竟发现了什么？**

**Academic Writing** 是一个帮助 AI 按你的意愿修订论文的写作 skill。它先了解你想改善什么、希望小改还是大改，再针对所选问题动笔，保留已经清楚、有效的表达，让研究的逻辑、思想和贡献更容易被读者理解。

## 🚀 怎么开始？

在能够读取 GitHub 内容的 Codex 或网页端 AI 中，可以直接复制下面的提示词。

### ⚡ 一句话开始

> https://github.com/Apprenticew/academic-writing 据此修改我的论文。

AI 应读取仓库中的 `SKILL.md`，按照其中的流程询问你的选择，再使用相应参考文件。**默认仅预选“减弱防御性写作”，其他功能不开启；仍会先让你确认或改选，并确定小改还是大改，再阅读和修改稿件。**

### 🎯 指定方向与小改

> 阅读 https://github.com/Apprenticew/academic-writing 中的 SKILL.md，只改善论文第二节的逻辑关联，做小改。保留现有段落安排，以及有助理解的连接词和从句。

### 🧭 指定范围内大改

> 阅读 https://github.com/Apprenticew/academic-writing 中的 SKILL.md，重点改善引言的故事与篇章组织，允许大改，包括重排和改写有问题的段落。其他章节保持不变。

已经明确的方向与幅度会直接沿用，无需重复选择，也不会额外附加默认功能。你可以同时提供稿件，或在确认选择后再提供。

通过链接使用适用于当前对话。如需在 Codex 中反复调用，可按下方说明安装。若当前工具无法读取仓库内容，可下载仓库，将 `SKILL.md` 和 `references/` 中的文件作为附件提供。

**从一段最想改善的文字开始，选好方向，试试看。**

## 🎯 你想改善什么？

| 选项 | 修改重点 |
|---|---|
| 🛡️ **1. 减弱防御性写作** | 减少无必要的自我削弱、预先辩解和防御性铺垫。 |
| 🔗 **2. 改善逻辑关联** | 改善句段承接、连接词、副词、重音和前后呼应。 |
| 🖋️ **3. 改善词语与学术表达** | 改善生硬、口语化的措辞和搭配，使用自然的领域表达。 |
| 🧭 **4. 改善故事与篇章组织** | 突出核心认识与贡献，让实验、概念和章节形成连贯推进。 |

你可以多选，也可以只选其他方向；“减弱防御性写作”同样由你决定是否使用。

## 🎛️ 改动多大，由你决定

- **小改：** 保留现有故事、章节结构及有效句子，针对具体问题局部调整或补足表达。
- **大改：** 围绕选定方向重写有问题的段落；故事重构、贡献重新定位或章节调整，由你决定是否纳入。

未说明改动幅度且会影响改法时，会先询问。即使选择全文修订，也只改实际存在所选问题的位置，保留其余有效表达。

在需要修改的位置，鼓励充分保留和补充过渡语、连接词、副词、从句与状语从句，让人类读者看清因果、转折、目的和条件。句子应有始有终，避免短促、孤立的单句；为把关系说清楚，可以适当增加字数。

## 📦 在 Codex 中长期使用

将本仓库内容放入名为 `academic-writing` 的文件夹，再放到项目的 `.agents/skills/` 或个人的 `~/.agents/skills/` 目录下。项目安装后的入口应为 `.agents/skills/academic-writing/SKILL.md`。安装与发现机制可参考 [Codex 官方技能文档](https://learn.chatgpt.com/docs/build-skills)。

安装后，可以直接调用：

> 使用 $academic-writing 帮我修改论文，先让我选择修改方向和改动幅度。

skill 指令以中文编写，可用于中英文稿件的写作讨论与修订。

## 📚 写作参考

- [Jennifer Widom：技术论文写作建议](https://cs.stanford.edu/people/widom/paper-writing.html#abstract)

  通过五个问题组织引言思路，并以具体论文解释其应用。

[参考资料说明](references/writing-guides.md)概括两篇文章的用途，可用于组织思路和检查内容是否完整；具体段落数与贡献形式仍由论文需要及投稿规范决定。
